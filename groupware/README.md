# 社内グループウェア（クロジカ スケジュール管理の置き換え）

クロジカ スケジュール管理の主要機能を、自社で運用できる形で置き換えるための Web アプリです。
外部の有料サービスやライブラリに依存せず、Node.js だけで動きます。

## 機能

| 機能 | 内容 |
| --- | --- |
| スケジュール | 部署・全員・自分の週表示、予定の登録/編集/削除/複製、終日予定、繰り返し（毎日・平日・毎週・毎月）、非公開予定（参加者以外には「予定あり」と表示） |
| 施設予約 | 会議室・社用車などの週表示。同じ時間帯の重複予約を防止 |
| 日程調整 | 候補日時を出して参加者が ○△× で回答。各候補で既存の予定が入っている人を「予定あり」と表示。主催者が決定すると参加者全員のスケジュールに自動登録（施設の同時予約も可） |
| ワークフロー | 稟議・経費精算・休暇申請など。最大6段階の直列承認、承認/差し戻し/却下、差し戻し後の再申請、取り下げ |
| 掲示板 | お知らせの投稿、【重要】の上部固定（管理者）、既読者の確認 |
| テンプレート集 | 収支シミュレーション・ローン計算・業務自動化のマクロ/スクリプトなどのファイルを分類ごとに掲載。説明と使い方、版の履歴（更新しても過去の版を保持）、ダウンロード数。マクロを含む形式には注意表示 |
| ブログ | 社員が自由に記事を投稿。キーワード・投稿者で検索、いいね、コメント |
| チャット | 1対1・グループのトーク。未読件数の表示、新着は自動で反映（数秒ごと） |
| ToDo | 自分のやること管理に加え、他の社員への依頼（依頼した ToDo の進み具合を確認可能） |
| ホーム | 今日の予定、承認待ち・チャット未読・日程調整の未回答の件数、未読お知らせ、ToDo |
| システム管理 | ユーザー・部署・施設の管理、CSV 一括登録、予定の CSV 取込/書出、パスワード初期化、操作ログ |

## セキュリティ

- パスワードは scrypt でハッシュ化して保存（10文字以上・英数字混在を必須）
- 初回ログイン時と管理者による初期化後は、パスワード変更が済むまで他の操作をできません
- ログインの連続失敗を制限（同一ID・同一端末から15分で10回まで）
- セッションは HttpOnly Cookie（12時間操作がないと失効）、更新操作は CSRF トークンで保護
- Content-Security-Policy などのセキュリティヘッダーを付与。画面は innerHTML を使わずに描画（XSS 対策）
- テンプレート集のファイルは常にダウンロード扱いで返し、ブラウザ内で開かせない。実行ファイル（.exe/.bat/.js 等）は登録不可
- ログイン・承認・ユーザー管理などを操作ログに記録

## 動かし方（お試し）

Node.js 22.13 以上が必要です。

```
cd groupware
npm start
```

初回起動時に管理者アカウント（ログインID `admin`）が作られ、初期パスワードがコンソールに表示されます。
ブラウザで http://localhost:3000/ を開いてログインしてください。

テスト: `npm test`

## 本番運用

### 推奨構成（30〜100名規模）

- 社内サーバーまたはクラウドの小型 VM 1台（目安: 2vCPU / 2GB メモリ / 20GB ディスク）
- 前段にリバースプロキシ（nginx、Caddy など）を置いて **HTTPS 化**してください（nginx の場合はアップロード上限 `client_max_body_size 50m;` も設定）
- データは SQLite ファイル1つに保存されます。100名規模なら十分な性能です

### Docker で起動する場合

```
cd groupware
docker build -t groupware .
docker run -d --name groupware -p 3000:3000 \
  -v groupware-data:/data \
  -e COOKIE_SECURE=1 -e TRUST_PROXY=1 \
  --restart unless-stopped groupware
docker logs groupware   # 初期パスワードの確認
```

### 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス（プロキシ経由のみにするなら `127.0.0.1`） |
| `DB_FILE` | `./data/groupware.db` | データベースファイルの場所 |
| `FILES_DIR` | DB と同じ場所の `files/` | テンプレート集のファイルの保存先 |
| `MAX_UPLOAD_MB` | `50` | アップロードできるファイルの上限（MB） |
| `ADMIN_LOGIN_ID` | `admin` | 初回起動時に作る管理者のログインID |
| `ADMIN_PASSWORD` | （自動生成） | 初回起動時の管理者パスワード |
| `COOKIE_SECURE` | なし | HTTPS で運用する場合は `1`（必須） |
| `TRUST_PROXY` | なし | リバースプロキシ配下では `1`（ログイン制限に実際の接続元IPを使う） |
| `TZ` | OS の設定 | 会社の時刻帯。`Asia/Tokyo` を推奨 |

### バックアップ

稼働中でも安全にバックアップできます。データベースに加えて、テンプレート集のファイルもまとめて保存します。cron などで毎日実行してください（既定で直近30世代を保持）。

```
npm run backup            # ./backups に保存
BACKUP_DIR=/mnt/nas/gw npm run backup
```

復元はサーバーを停止し、バックアップファイルを `DB_FILE` の場所に、`backups/files/` の中身を `FILES_DIR` にコピーして起動します。
バックアップは別のディスクや NAS にも置いてください。

## クロジカからの移行

1. **部署・施設を登録**：システム管理 →「部署」「施設」
2. **社員を一括登録**：システム管理 →「データ移行」→ ユーザー CSV
   - 列: `ログインID, 氏名, メールアドレス, 部署名, 権限(admin/member)`
   - 登録後に表示される初期パスワードを各社員へ配布（初回ログイン時に変更が必要）
3. **予定を取り込み**：クロジカから予定を CSV で書き出し、次の列順に Excel 等で整えて取り込みます
   - 列: `件名, 開始日時, 終了日時, 終日(1/0), 参加者ログインID(;区切り), 施設名(;区切り), 場所, メモ, 非公開(1/0)`
   - 日時は `2026-04-01 09:00` または `2026/4/1 9:00` 形式
   - Excel で保存した Shift_JIS の CSV もそのまま取り込めます
   - 取り込めなかった行は行番号と理由が表示されます
4. 並行運用期間を設け、問題がなければクロジカを解約

ワークフローの過去データ・掲示板は、必要なものだけ手作業で移すか、クロジカ側で PDF 等に保存しておくことをお勧めします。

- チャット・ブログへのファイル添付、チャットの既読表示

- Google / Microsoft 365 アカウントでのシングルサインオン
- 祝日表示、日表示・月表示
- ワークフローの申請フォームの項目カスタマイズ、添付ファイル
- 予定の空き時間検索

## 構成

```
groupware/
  server.mjs          起動スクリプト
  lib/
    app.mjs           認証・CSRF・ルーティング
    auth.mjs          パスワード・セッション
    db.mjs            データベース定義
    http.mjs          HTTP 処理
    validate.mjs      入力チェック・日付・CSV
    api/              機能ごとの API（users / events / polls / workflow / board / blog / chat / templates）
  public/             画面（HTML / CSS / JavaScript）
  scripts/backup.mjs  バックアップ
  test/               API テスト
```
